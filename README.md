# Heart Disease Prediction API (FastAPI + Docker + Render)

A simple binary classification API. It uses a scikit-learn pipeline (feature
scaling + Logistic Regression), served by FastAPI and packaged with Docker.

> Educational project only. This model is not a medical device and must not
> be used to diagnose, treat, or make health decisions.

## 1. Prepare and train the model

1. Download the CSV from [Kaggle Heart Disease Dataset](https://www.kaggle.com/datasets/johnsmith88/heart-disease-dataset).
2. Put the CSV at `data/heart.csv`. The expected columns are `age, sex, cp,
   trestbps, chol, fbs, restecg, thalach, exang, oldpeak, slope, ca, thal,
   target`.
3. Create an environment and install dependencies:

   ```bash
   python -m venv .venv
   # Windows: .venv\Scripts\activate
   # macOS/Linux:
   source .venv/bin/activate
   pip install -r requirements.txt
   ```
4. Train and save the model:

   ```bash
   python train.py
   ```

This creates `model/heart_model.joblib`. Commit this file to GitHub so it is
included in the Docker build. Do not commit the dataset if its license or
terms do not permit redistribution.

## 2. Run locally without Docker (optional)

```bash
uvicorn app.main:app --reload
```

Open http://localhost:8000/docs.

## 3. Build and run with Docker Compose

Run these commands from the project root, after creating the model file:

```bash
docker-compose build
docker-compose up
```

With newer Docker Compose installations, use `docker compose build` and
`docker compose up`.

- Swagger UI: http://localhost:8000/docs
- Health: http://localhost:8000/health
- Info: http://localhost:8000/info

Test prediction:

```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
    "age": 63,
    "sex": 1,
    "cp": 3,
    "trestbps": 145,
    "chol": 233,
    "fbs": 1,
    "restecg": 0,
    "thalach": 150,
    "exang": 0,
    "oldpeak": 2.3,
    "slope": 0,
    "ca": 0,
    "thal": 1
  }'
```

Response format:

```json
{
  "heart_disease": true,
  "prediction": 1,
  "probability": 0.81
}
```

The probability shown above is only an example; your trained model will return
its own value.

## 4. Deploy to Render

1. Push the complete project to a GitHub repository. Include
   `model/heart_model.joblib`; it is generated after training.
2. In Render, choose **New + → Web Service** and connect the repository.
3. Set **Runtime/Environment** to **Docker**. Set the root directory to the
   repository root if the Dockerfile is there.
4. Deploy. Render detects the Dockerfile and builds the image. The app listens
   on `0.0.0.0:8000`; Render routes external traffic to the container.
5. When deployment finishes, test:
   - `https://YOUR-SERVICE.onrender.com/health`
   - `https://YOUR-SERVICE.onrender.com/info`
   - `https://YOUR-SERVICE.onrender.com/docs`

If your Render service settings expose a port configuration, use the port
expected by the Dockerfile (`8000`). Do not set a separate start command unless
you intentionally override the Dockerfile CMD.

## API endpoints

| Method | Route | Purpose |
|---|---|---|
| GET | `/health` | Health and model-loaded status |
| GET | `/info` | Model description and feature list |
| POST | `/predict` | Predict binary heart disease output |

`/predict` expects all 13 features as JSON. Pydantic validates basic ranges
and types. `heart_disease: true` means the model predicts target class 1.

## Troubleshooting

- **Model file missing:** run `python train.py` and ensure
  `model/heart_model.joblib` exists before building the Docker image.
- **CSV columns differ:** inspect the downloaded CSV headers and update
  `FEATURES`/`required` in `train.py` to match. This solution expects the
  common Kaggle file with a `target` column.
- **Container exits on startup:** inspect logs with `docker-compose logs`.
- **Port already in use:** change the left side of the Compose mapping, e.g.
  `8001:8000`, then open `http://localhost:8001/docs`.
